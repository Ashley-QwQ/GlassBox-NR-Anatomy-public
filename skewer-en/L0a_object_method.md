## Which Object We Are Explaining

The target object is fixed as nvngx_dlssnr.dll **310.8.0.0, sample C, [SHA](APPENDIX_beginner_glossary.md#g103)-256 prefix e16bcf15e16e13f5…**. Existing read-only artifact verification gives the full file SHA, version, and 165,840,496 B length, [experiments/parity-cpp-param-change-r01-20261024-codex/stage_d2_followup/RESULT_ZH.md:9](../../../experiments/parity-cpp-param-change-r01-20261024-codex/stage_d2_followup/RESULT_ZH.md#L9); for the valid NVIDIA signature identity of sample C and the [WEIGHTS_HT](APPENDIX_beginner_glossary.md#g079) resource identity, see [ARCHITECTURE_V3_ZH.md:264–274](../../../ARCHITECTURE_V3_ZH.md#L264). Here "network" refers to the compute trunk of this fixed object under named inputs, controls, and [history](APPENDIX_beginner_glossary.md#g024) [state](APPENDIX_beginner_glossary.md#g002): B0 conditioning input, [encoder](APPENDIX_beginner_glossary.md#g009), [bottleneck](APPENDIX_beginner_glossary.md#g010), decoder, and B70 state exit; this skewer also explains the adjacent color copy, [workspace](APPENDIX_beginner_glossary.md#g082) initialization, [rearrangement](APPENDIX_beginner_glossary.md#g019), history copy, and display postprocessing so that a single frame is wired from input to output. The default route is [launch](APPENDIX_beginner_glossary.md#g080) [L0](APPENDIX_beginner_glossary.md#g081)–L157, with [B numbers](APPENDIX_beginner_glossary.md#g036) kept separate from launch numbers; it does not represent all functional paths of the [DLL](APPENDIX_beginner_glossary.md#g078) or a unique training architecture. [ARCHITECTURE_V3_ZH.md:147–167](../../../ARCHITECTURE_V3_ZH.md#L147); computation explanations for each stage start from [L0](L0_frame.md).

Accordingly, the native object, the [CPU reconstruction](APPENDIX_beginner_glossary.md#g100), and the result records must be read separately: the first is the observed computation behavior, the CPU source code gives an executable reproduction hypothesis, and the result records test whether that hypothesis holds under specified inputs and comparison scopes; the results cannot uniquely invert the native internal structure or training purpose. [ARCHITECTURE_V3_ZH.md:63–80, 1413](../../../ARCHITECTURE_V3_ZH.md#L63).

## Using Reproduction to Discriminate Computation Hypotheses

This skewer sets the gate for "the CPU reconstruction holds over the measured scope" on actual bytes: the CPU recomputes from bound inputs and pre-states, compares launch by launch over the observed ROLE/D/FULL/texture scopes, and simultaneously checks FINAL; when a continuous chain is claimed, the CPU must also advance to the next launch or next frame using its own state. When only FINAL is recorded, the conclusion stops at FINAL; points without native observation remain NOT_OBSERVED. This distinction comes from [ARCHITECTURE_V3_ZH.md:72, 118–125](../../../ARCHITECTURE_V3_ZH.md#L72) and [named continuous-chain records:19–32](../../../experiments/parity-cpp-4k-multiframe-r01-20261022-codex/RESULT_ZH.md#L19).

This is a stronger criterion than visual similarity or numerical closeness within a tolerance: byte comparison requires even the least significant bit, the sign of zero, and the [publication](APPENDIX_beginner_glossary.md#g091) encoding to match, so small errors cannot be masked by display or error thresholds. Per-launch comparison adds another layer of discrimination beyond the final image alone: a wrong fetch/writeback layout, [quantization](APPENDIX_beginner_glossary.md#g061) position, accumulation grouping, rounding/[FTZ](APPENDIX_beginner_glossary.md#g068), texture filtering, or history carry will falsify the hypothesis for that scope as soon as it causes a single-byte difference on the tested input and compared points; equivalent hypotheses that do not trigger a difference may still pass simultaneously. For the specific preserved publication points, see [INDEX Computation Conventions](INDEX.md#computation-conventions); for the actual FULL/POST/FINAL denominators, see [4K RESULT_ZH.md:23–46](../../../experiments/parity-cpp-4k-multiframe-r01-20261022-codex/RESULT_ZH.md#L23).

For example, in the scene control records, altering the consumed history or reset parameters indeed makes FINAL differ, whereas the reset-isolation controls remain equal as expected; these controlled comparisons test specific explanations such as "the saved images merely happened to be identical" or "the corresponding state was never consumed at all", while the conclusion remains restricted to the measured controls. [experiments/parity-cpp-1080-multiparam-r03-20261018-claude/RESULT_ZH.md:27–36](../../../experiments/parity-cpp-1080-multiparam-r03-20261018-claude/RESULT_ZH.md#L27). The multiframe result ledger remains in the [evidence appendix](APPENDIX_evidence_history.md#history-evidence).

<a id="limits"></a>
## Boundaries of Byte Equality

What testing proves is equality over the specified version, inputs, pre-state, parameters, fill, and comparison scope; a finite sample size cannot be turned into "equal for all inputs", nor does matching at the exit establish a unique network decomposition, training semantics, or general memory/scheduling correctness. Current project wording requires explicitly retaining rejections, unknowns, and failures, [ARCHITECTURE_V3_ZH.md:76–80](../../../ARCHITECTURE_V3_ZH.md#L76).

The [full-domain](APPENDIX_beginner_glossary.md#g111) goal is recorded separately and currently remains **NOT_ESTABLISHED**: the architecture status lists 0/12 roots, 0/92,992 full state transitions, and 37 hardware premises, [ARCHITECTURE_V3_ZH.md:7](../../../ARCHITECTURE_V3_ZH.md#L7); the conditional proof skeleton requires software, layout, domain, translation, termination, and hardware assumptions to be closed separately, and both categories currently have open items, [docs/arch-v2/08_proof.md:40](../../arch-v2/08_proof.md#L40). Finite primitive agreement, 158-launch coverage, and named continuous chains cannot substitute for that goal.

This page only organizes saved records; this round adds no new native captures, CPU models, or continuous-chain runs.
