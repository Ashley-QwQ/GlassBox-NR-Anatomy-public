## One Resource, Three Shape Conventions

Fixed sample C has only a single weight-like PE [resource](APPENDIX_beginner_glossary.md#g079), WEIGHTS_HT, of length 147,695,410 B; the resource table contains no second weight resource separated by preset or feature. This conclusion does not prove that every runtime upload is identical. [Read-only resource check RESULT:9–22](../../../experiments/parity-cpp-param-change-r01-20261024-codex/stage_d2_followup/RESULT_ZH.md#L9).

**153 is the number of serialized packed entries, not 153 ordinary dense parameter [matrices](APPENDIX_beginner_glossary.md#g051).** The release extractor preserves each entry's name, shape metadata, and payload, storing the payload as 1D U8; it explicitly avoids guessing dense FP16 shapes or mixed-precision segmentation. [Public extract_dlssnr_weights.py:1–9, 29–31, 85–98](https://github.com/Ashley-QwQ/GlassBox-NR/blob/e4a9b4214c723015ff4a99d73f13aa9a4a8ed1ec/third_party/mlxdlss/tools/extract_dlssnr_weights.py#L1). One must therefore distinguish:

- The dimensions=[N], dtypeCode=1, and byteCount=2N recorded in the resource; this is only a serialized structural relationship, and one cannot treat the entire payload as an ordinary [F16](APPENDIX_beginner_glossary.md#g054) matrix on the basis of code=1. [make_weights.py:11–19, 216–238](https://github.com/Ashley-QwQ/GlassBox-NR/blob/e4a9b4214c723015ff4a99d73f13aa9a4a8ed1ec/devkit/make_weights.py#L11).
- The container's U8[2N] holding the same payload bytes; a single entry can simultaneously contain [E4](APPENDIX_beginner_glossary.md#g055) matrices, F16 [vectors](APPENDIX_beginner_glossary.md#g076)/biases, [F32](APPENDIX_beginner_glossary.md#g056) [scales](APPENDIX_beginner_glossary.md#g031), and internal alignment. [make_weights.py:263–286](https://github.com/Ashley-QwQ/GlassBox-NR/blob/e4a9b4214c723015ff4a99d73f13aa9a4a8ed1ec/devkit/make_weights.py#L263), [TIN typed loader:34–52](https://github.com/Ashley-QwQ/GlassBox-NR/blob/e4a9b4214c723015ff4a99d73f13aa9a4a8ed1ec/cpp/chain_tin_optm/tin.cpp#L34).
- The [decoded](APPENDIX_beginner_glossary.md#g057) matrices/vectors and their concrete layouts seen by CPU arithmetic. E4 can be expanded to F16 to participate in reconstruction, so storage size cannot be doubled on the basis of the expanded type; nor can the packed 1D N be treated as a network [channel](APPENDIX_beginner_glossary.md#g007) count. [B0 loader:7–20](https://github.com/Ashley-QwQ/GlassBox-NR/blob/e4a9b4214c723015ff4a99d73f13aa9a4a8ed1ec/cpp/chain_entry_optm/b00.hpp#L7), [weight format boundaries](L3_qmma_e4m3.md).

This round reads only the 8 B length and 32,528 B JSON header of the existing container; **0 B of payload is read**. For the whitelisted projection and integer summary of the 153 names, dimensions, and sizes, see the [metadata receipt](../skewer/examples/r04k.weights_layout.json); for the reading boundary, see [script:29–61](../skewer/examples/weights_layout_r04k.py#L29). Payload [SHAs](APPENDIX_beginner_glossary.md#g103) were not re-verified, and numeric identity continues to follow the existing [five-file derivation acceptance](../../../experiments/parity-cpp-v2-weights-derive-r01-20261021-claude/RESULT_ZH.md#L18); no coefficients, per-entry hashes, or byte dumps are emitted.

## How Entries Map to Stages and Launch Families

The naming convention is blockB.layerJ.layer, with block70.layer0.blend_scale in addition for B70. B is the [logical block](APPENDIX_beginner_glossary.md#g036) and J is the parameter-package index within that block; a single [TIN](APPENDIX_beginner_glossary.md#g011) package is consumed by a single fused launch, whereas multi-package [split16](APPENDIX_beginner_glossary.md#g013) and [ViT](APPENDIX_beginner_glossary.md#g014) blocks supply multiple launches respectively. See [L0](L0_frame.md) for the corresponding default launch table; actual fetching still follows parameter bindings and CPU [provenance graphs](APPENDIX_beginner_glossary.md#g089), and the names themselves are not proof of native layout.

| Stage / block | Entry organization and consuming families | Shapes / dtypes of arithmetic matrices and auxiliary items ([CPU reconstruction](APPENDIX_beginner_glossary.md#g100) convention) |
|---|---|---|
| B0 | Single package B0.J0 for the L2 input fused kernel | E4 of 32×128, 128×32, 32×96, 32×32; plus F16 16×32 adapter, 32-channel [residual](APPENDIX_beginner_glossary.md#g017) scales, and 64×64 biases, with F32 [query scale](APPENDIX_beginner_glossary.md#g052) converted to half after loading. [b00.hpp:7–20, 46](https://github.com/Ashley-QwQ/GlassBox-NR/blob/e4a9b4214c723015ff4a99d73f13aa9a4a8ed1ec/cpp/chain_entry_optm/b00.hpp#L7) |
| TIN Encoder B1–B22 / Decoder B48–B69 | One J0 package per block; consumed by stage across [inpview](APPENDIX_beginner_glossary.md#g022)/chained/ds_wait/upsample/outview | For C=32, E4 [feed-forward](APPENDIX_beginner_glossary.md#g037) 32×128→128×32; for C≥64, packed matrix slots C×(4C+128) and C×C; plus [QKV](APPENDIX_beginner_glossary.md#g040) C×3C, output projection C×C, and additional 2C×C / C×2C for up/[downsampling](APPENDIX_beginner_glossary.md#g021). ## Per-Stage Byte Counts Derived from Recorded Shapes

Below, N is always the element count from the resource's dimensions=[N]. Writing A(N)=512×ceil(2N/512), each entry has [payload](APPENDIX_beginner_glossary.md#g097) 2N B and upload slot A(N) B; the formulas are computed from the metadata of all 153 entries without reading payloads. For the grouping breakdown, see [script:14–19, 45–78](../skewer/examples/weights_layout_r04k.py#L14) and [complete metadata](../skewer/examples/r04k.weights_layout.json).

ΣA(N)=147,719,680 B, of which inter-slot and tail padding account for 35,902 B in total; the raw resource of 147,695,410 B instead contains 11,632 B of record framing. **The stage slot totals sum entries by stage attribution and do not claim that each stage necessarily forms a single contiguous interval inside the raw resource.** The read container header is sorted by name, so the original resource order cannot be inferred backward from it either.

<a id="layouts"></a>
## 512 B Upload Layout and Other Containers

device_weights.bin concatenates entries in resource appearance order, padding after each payload to a multiple of 512 B and also padding the final entry; this is the exact 147,719,680 B layout. [make_weights.py:245–252](https://github.com/Ashley-QwQ/GlassBox-NR/blob/e4a9b4214c723015ff4a99d73f13aa9a4a8ed1ec/devkit/make_weights.py#L245). weights-device.bin and weights_gpu.bin sort by name, align before each entry, and do not pad the final tail, giving a length of 147,719,232 B; their layout differs from device_weights.bin, so they cannot be wired to the same pointer on the basis of total size alone. The raw resource weights.bin and the U8 container are yet other distinct formats. [make_weights.py:21–31, 255–261](https://github.com/Ashley-QwQ/GlassBox-NR/blob/e4a9b4214c723015ff4a99d73f13aa9a4a8ed1ec/devkit/make_weights.py#L21), [five-file derivation RESULT:8–22](../../../experiments/parity-cpp-v2-weights-derive-r01-20261021-claude/RESULT_ZH.md#L8).

## Where Scale Factors Take Effect

Only locations and types are described here, without listing any coefficient values. Per-channel F16 scales in FFN and attention multiply the bypass first and then serve as the matrix [seed](APPENDIX_beginner_glossary.md#g042) or the input to an ordered merge; they cannot be moved to a single high-precision addition at the end. [Residual interfaces](L3_ffn.md#residual). The sin vector in TIN upsampling acts on the skip merge, B39's vector is likewise used for skip fusion, and B70's sin/cos vectors act on the merge of decoded [features](APPENDIX_beginner_glossary.md#g008) with B0 features; these names do not mean trigonometric functions are called. [tin.cpp:151–159](https://github.com/Ashley-QwQ/GlassBox-NR/blob/e4a9b4214c723015ff4a99d73f13aa9a4a8ed1ec/cpp/chain_tin_optm/tin.cpp#L151), [entry.cpp:71](https://github.com/Ashley-QwQ/GlassBox-NR/blob/e4a9b4214c723015ff4a99d73f13aa9a4a8ed1ec/cpp/chain_entry_optm/entry.cpp#L71), [outtail.cpp:86–90](https://github.com/Ashley-QwQ/GlassBox-NR/blob/e4a9b4214c723015ff4a99d73f13aa9a4a8ed1ec/cpp/chain_outtail_optm/outtail.cpp#L86).

Query scales are per-head F32 resource fields, converted to half according to the specific graph/loader and applied to Q after [normalization](APPENDIX_beginner_glossary.md#g043); the corresponding normalization of K does not add a learned scale of the same kind. [TIN loader:50, norm:114–121](https://github.com/Ashley-QwQ/GlassBox-NR/blob/e4a9b4214c723015ff4a99d73f13aa9a4a8ed1ec/cpp/chain_tin_optm/tin.cpp#L50), [graph constraints for split16/ViT](L3_norm_nonfinite.md#affine). ViT attention_scalar is a named item in the parameter list: the attention parameters of B31–B38 point at their own entries, but neither the public runtime nor the saved attention graphs contain a consuming edge from it to the score [affine](APPENDIX_beginner_glossary.md#g049); the score affine slope/addend are graph constants whose traceable source is an F32 literal constant in the kernel converted to half, and there is no evidence that they were folded from attention_scalar, so implementations must not multiply by this scalar again ([F06 trace](../../../experiments/anatomy-f06-attention-scalar-r01-20261031-codex/RESULT_ZH.md), consistent in 8/8 blocks; proprietary training/export history is outside this conclusion). blend_scale belongs to B70 [temporal](APPENDIX_beginner_glossary.md#g024) confidence blending; neither is a generic output gain. [ViT scores](L3_attention_softmax.md#attention-softmax), [B70 blending](L3_b70_history_output.md#b70-temporal).

The gain, [intensity](APPENDIX_beginner_glossary.md#g004), frame word, and control values in the [host](APPENDIX_beginner_glossary.md#g096) [CB](APPENDIX_beginner_glossary.md#g083), together with the certified noise and [MUFU](APPENDIX_beginner_glossary.md#g073) function assets, belong to parameters or function assets respectively; they do not thereby become a 154th weight entry.
